# Petaricon Editor

スマホ単体でも使える `.slint` のノーコードエディタです。Rust と Slint で書かれていて、Android と PC の両方で動きます。キャンバスでは `slint-interpreter` が本物の描画を行い、編集結果は人が読んで手直しできる `.slint` テキストとして保存されます。知らない記述は変更せずそのまま残します。

設計は `docs/superpowers/specs/2026-10-20-slint-touch-editor-design.md` を参照してください。

## 基本的な使い方

1. プロジェクトを作る(または開く)。
2. 「Parts」タブから部品を追加し、キャンバスの上でラフに配置する(ドラッグで移動、四隅のハンドルでサイズ変更)。部品は選択中のコンテナ(何も選んでいなければ画面全体)に追加され、追加後もそのコンテナが選択されたままなので、続けて押すと兄弟として並びます。追加した部品を動かすときは、その部品をタップして選びます。
3. コンテナを選んで **Tidy** か **Stack** を押す(違いは下の「Tidy と Stack」)。
4. レイアウトのガイドに出る数値(spacing、padding)をタップして、数値で調整する。
5. 繰り返したい部分を選んで **Extract** を押し、`component` に切り出す。必要なら `in property` と `callback` も宣言する。
6. 部品の中の値を **引数** にして、使う側から渡す(下の「引数」)。
7. **Save** で保存する。

### Props とプレビューの値の書き方

Props の `text` と、プレビュータブの `string` 型の値(`@名前` の欄)は同じ書き方です。

- `text` は、中身が普通の文字列リテラルなら引用符なしの文字をそのまま入力します(`"` や `\` も、保存時に自動で退避します)。式にしたいときは先頭に `=` を付けます(例: `=root.label`)。式の `text` は `=` つきで表示され、`=` を消すと文字列に戻ります。`=` で始まる文字そのものは `==` で書きます。`=` だけの入力は式がないので反映せず、理由を出します。
- プレビューの値も同様です。`string` は上の規則(普通に打てば文字列、先頭 `=` で式、`==` で `=` で始まる文字、空で未設定)に従い、`bool` / `int` / `float` / `length` は今までどおりの入力です。それ以外の型(配列・構造体など。文字列リテラルの形がない型)は式のテキストをそのまま入力し、先頭に `=` を付けても付けなくても同じ式になります(`=` だけは断ります)。`.preview` に保存されるのは今までどおり Slint の式なので、ファイルの形式は変わらず、古い `.preview`(`"abc"` など)もそのまま使え、欄には `abc` と出ます。
- 構文エラーや、コンパイルが通らなくなる値は反映せず、入力欄の下に「この値は使えません: …」と出します(文書は変わりません)。入力途中の状態は欄を書き換えず、有効な値になった時点で反映します。
- 文書が壊れているとき(ソースタブでの編集など)も、元に戻す/やり直す、ツリーからの削除、壊れた値の再入力は使えます。エラー帯の「(元に戻す か ソース で直せます)」が目印です。
- Android は英語(ASCII)キーボードだけに対応します(日本語入力の変換中の文字の重複を避けるため。`third_party/i-slint-backend-android-activity/PETARICON.md`)。貼り付けなら日本語も入力できます。

## 引数

部品(`component`)の中の値を引数(`in property`)にして、その部品を使う側から値を渡せます。

- **引数にする**: 部品の中を開いて(使っている場所を選んで「中を開く」)中の要素を選ぶと、Props の行のうち値が書かれていて引数にできるものに「引数にする」が出ます。押すと名前(初期値 `<id か型の小文字>-<プロパティ名>`、あれば `-2` ...)を入れるダイアログが開きます。型が `text`→`string`、`x`/`y`/`width`/`height`/`font-size`/余白など→`length`、`color`/`background`→`brush` のように名前から決まらないときは型も選びます(使う側の引数の行からやる場合は、部品が宣言している型を使います)。OK を押すと、部品のルートに `in property <型> 名前: 元の式;` が足され、元の行は `プロパティ: root.名前;` になります。既定値が元の式なので、どの利用の見た目も変わりません。1 回の Undo で戻ります。
- 断る場合(理由を表示、何も変わりません): 値が書かれていない、式に `self` / `parent` が含まれる、すでに `root.名前` だけ、要素自身で宣言したプロパティ、`<=>` の行、名前が使えない/すでにある、コンパイルが通らなくなる。ボタンは、引数にできる行にだけ出ます。
- **利用側**: 部品の利用を選ぶと、Props の位置と大きさ(x/y/width/height)の次に、その部品の `in` / `in-out` プロパティが宣言順に「名前と型」つきで並びます(`out` とコールバックは出ません)。値は書かれている式で、書かれていなければ空欄に部品の既定値が薄く出ます。値の書き方は Props と同じです(`string` は文字をそのまま、先頭 `=` で式。`length` は数だけなら `px` を補う。`bool` ほかは式のテキスト、`true` / `false` など)。入力すると利用側に `名前: 値;` が書かれ、プレビューに反映されます。空にすると書かれた値を消して、既定値に戻ります。
- 部品が別のファイルにあっても、`import` をたどって宣言を読みます。定義が見つからない/読めないとき(壊れた `import` など)は、引数の行は出ず、エラーも出しません。

## Tidy と Stack

どちらも、選んだコンテナの直下の子だけを対象にします(孫以下は触りません)。

- **Tidy**: 自由配置のまま、子の位置と寸法を「意図していそうなきれいな値」に寄せます。L 字は L 字のまま、ずれだけが直ります。レイアウト要素は挿入しません。書き換えるのは子の `x` / `y` と、明示的に書かれている `width` / `height` だけで、整数の `px` で書きます(寸法が書かれていない子の寸法は変えません)。1 回の Tidy は 1 回の Undo で戻ります。
  - 見つけて適用する関係: そろえ(左・中央・右/上・中央・下)、等間隔、同じずれの繰り返し、対称(コンテナの中心線など)、寸法そろえ。
  - 実行後、適用した関係がキャンバスに重なって表示されます(そろえ・対称は点線、等間隔はすき間の印、繰り返しは組の左上をつなぐ点線、寸法そろえは各要素の印)。次の編集、選択の変更、パネルのタブ切り替え、Undo/Redo で消えます。画面下に「そろえ 3・等間隔 1」のような要約が出ます。変更がなければ「整える箇所はありませんでした」と出ます。
  - 断る場合(何も変えません): レイアウト要素を選んでいる(先に **Unstack**)、コンテナではない、`for` / `if` の子がある、子が 0、プレビューが古い(コンパイルエラー中)。
- **Stack**: 子を縦一列・横一列のレイアウトに変換します(`HorizontalLayout` / `VerticalLayout`)。位置は spacing / padding の数値で表されるようになります。
- **許容値**: メニューの **Settings** で Tidy の許容値を `-` / `+` で変えます(4px 刻み、4〜48px、初期値 16px)。値が大きいほど離れた要素もそろえます。設定は保存先フォルダの `.settings` に `tidy_tolerance=16` の形(`key=value` の行)で保存され、起動時に読み込まれます。

整形を取り消したいときは **Unstack**(現在の見た目の位置で自由配置に戻す)か **Undo** を使います。

## 付き方

入れ物(や画面)の大きさが変わっても配置の意図を保つための、子ごと・軸ごとの「どこに付くか」です。レイアウトの子には出ません。

- **選ぶ**: Props の先頭に「横」「縦」の切り替えが出ます。横は 左 / 右 / 左右 / 中央、縦は 上 / 下 / 上下 / 中央。切り替えても今の見た目の位置と大きさは変わりません(1 回の履歴の手)。
- **書き方**: .slint の式そのものが正で、別のファイルには何も持ちません。右 = `x: parent.width - self.width - 8px;`、中央 = `x: (parent.width - self.width) / 2 + 4px;`、左右 = `x: 8px; width: parent.width - 8px - 8px;`(縦は `y` / `height` / `parent.height`)。
- **左右・上下**: 大きさの行は数の入力の代わりに「左右に付いています」(「上下に付いています」)と出ます。
- **式**: 上の形でない式で書かれた軸は「式」と出て、ドラッグと大きさ変更では動かしません(理由と、もう一方の軸は動いたことをトーストで知らせます)。付き方を選ぶとその軸を選んだ形に書き換えるので、そこから抜けられます。
- **ドラッグ・大きさ変更**: 付き方を保ったまま数だけを書き換えます。左・上のままの要素は今までと同じ書き方です。
- **印**: 選んだ要素の付いている辺に黄色の小さな印が出ます(右・下 = その辺、左右・上下 = 両方の辺、中央 = 真ん中の線。左・上は何も出ません)。
- **付き方を推定**: 自由配置の整え(Tidy)の後、キャンバスの左下に「付き方を推定」が出ます。入れ物の端との余白から子ごとに決めます(Tidy の許容差を使います): 両側の余白が許容差以内で幅が半分以上なら左右、左右の余白の差が許容差以内なら中央、右の余白が許容差より明らかに小さければ右、それ以外は左(縦も同様)。一覧(子 → 横/縦)を見て OK を押すと、見た目を変えずにまとめて書き換えます(1 回の履歴の手)。式の軸とレイアウトの子は対象外です。
- 入れ物の大きさ(や プレビュー の画面の大きさ)を変えて、付いた要素が追従するのを確かめられます。

## プロジェクトとファイルの管理

左上のメニューボタン(横線 3 本のアイコン)から操作します(ボタンはどれも 44px 以上)。

- **Projects**: 一覧から選んで切り替え、名前を入力して **Create** で新規作成、**Rename** で選択中のプロジェクトの名前を変更します。
- **Files**: **New file** で新しい `.slint` を作ってそのまま開きます(`.slint` は省略できます)。**Rename** は開いているファイルの名前を変更します。
- **Save as...**: 今のエディタの内容を、名前と保存先プロジェクト(初期値は現在のプロジェクト)を指定して新しいファイルに書き、そのファイルに切り替えます。元のファイルは、未保存の変更があっても最後に保存した内容のまま変わりません。
- 同じ名前が既にあるときや使えない名前(空、`/`、`\`、`..`、先頭が `.`)はダイアログにエラーを出して、何も変更しません。上書きはしません。
- 開いているファイル/プロジェクトの名前変更では、先に保存します(保存に失敗したら名前変更は中止)。名前変更後も同じ文書のまま編集を続けられ、`.bak` と復元用コピーも新しい名前に移ります。

## 複数ファイルのプロジェクト

プロジェクトのフォルダにある `.slint` ファイルは互いに `import { Panel } from "panel.slint";` で使い合えます(同じフォルダのファイルだけ。サブフォルダや `export { X } from "..."` の再公開は追いません)。素材(フォント `import "fonts/x.ttf";` や画像)もプロジェクトのフォルダからの相対パスで読み込まれます。サンプルは `testdata/controller-ui`(12 ファイル)です。

- **部品の使用は 1 つの要素として扱います**: `Panel { ... }` のように `component` を使っている箇所は、同じファイルのものでも別のファイルから `import` したものでも、キャンバスでタップすると使用箇所そのものが選ばれ、動かす・サイズを変える・消すのも 1 つのまとまりです(中の要素は選べません)。
- **中を開く**: 使用箇所を選んで **中を開く** を押すと、その `component` の定義を開きます。別のファイルならそのファイルに切り替わります(開く前に今のファイルを保存します。保存できなければ移動しません)。使えるのはプロジェクトのフォルダにある `.slint` の部品だけです(`std-widgets.slint` やサブフォルダは開けません)。
- **戻る**: 開いた順にたどって、元のファイル・部品・選択に戻ります(戻る前にも保存します)。ファイルを手で開く、名前を変える、Save as をすると、戻る履歴は消えます。
- **ファイルをまたぐジャンプでは、離れたファイルの Undo 履歴は残りません**(保存して、戻ったときに読み直すため)。同じファイルの中のジャンプでは Undo 履歴は保たれます。

## GitHub との同期

GitHub のリポジトリのフォルダをプロジェクトとして取り込み、編集したものを同じブランチへ送れます。git コマンドは使わず、GitHub の REST API(HTTPS)だけで動くので、スマホ単体で使えます。送った内容は普通の git のコミットになります。設計は `docs/superpowers/specs/2026-10-24-github-sync-design.md` を参照してください。

### トークンの作り方(fine-grained personal access token)

1. GitHub → 右上のアイコン → **Settings** → 左下の **Developer settings** → **Personal access tokens** → **Fine-grained tokens** → **Generate new token**。
2. **Repository access** で **Only select repositories** を選び、対象のリポジトリだけを選ぶ。
3. **Permissions** → **Repository permissions** → **Contents** を **Read and write** にする(ほかは不要)。
4. 期限を決めて作成し、表示された `github_pat_...` をコピーする(あとから見直せません)。

### トークンの入力と保管

- メニュー → **GitHub** の「設定」(未設定のときは「取り込む」「送る」を押しても入力を求めます)から、**入力バー**に貼り付けて OK。入力欄は伏せ字です。
- 保存先は `.github-token` の 1 ファイルです。**Android ではアプリ専用の内部ストレージ**(`internal_data_path`。他のアプリも USB 接続した PC も読めません)、PC では保存先フォルダ(`.settings` と同じ場所。所有者だけが読める権限で作ります)に置きます。プロジェクトのファイルにも `.settings` にも入らないので、GitHub へは送られません。以前の版が USB から見える `projects` 側に作った `.github-token` は、起動時に内部ストレージへ移して元を消します。
- 画面には末尾 4 文字だけ(`…abcd`)を出します。ログには書きません。エラーの文にトークンが含まれていても、画面に出す前に取り除きます。
- 「削除」で `.github-token` を消します。トークンを GitHub 側で失効させたときも、ここで消してください。

### 使い方(例: oumuamua-controller の UI)

対象: リポジトリ `Stew-000-1-0-011/oumuamua-controller`、ブランチ `ccr-1a4a2126-jaf9ht`、フォルダ `crates/app/ui`。

1. 上の手順でトークンを作る(リポジトリは `oumuamua-controller` だけ、Contents: Read and write)。
2. メニュー(横線 3 本)→ **GitHub から新しいプロジェクト**。
3. トークンが未設定なら「設定」から入力する。
4. 欄をタップして入力バーで入力する。リポジトリ `Stew-000-1-0-011/oumuamua-controller`、ブランチ `ccr-1a4a2126-jaf9ht`、フォルダ `crates/app/ui`。プロジェクト名は空なら「ui」(フォルダ名)になります。
5. **取り込む**。フォルダの下のファイルがすべて(サブフォルダ、フォント、画像も)新しいプロジェクト `ui` に入り、`main.slint`(なければ最初の `.slint`)が開きます。取り込む前に、開いていた文書は保存されます。
6. いつも通り編集して **Save**。
7. メニュー → **GitHub** → メッセージ(初期値「petaricon で編集」)を直して **送る**。手元で変えた・増やした・消したファイルが 1 つのコミットになり、同じブランチへ送られます(force はしません)。
8. PC やほかの端末で同じブランチが進んだら、メニュー → **GitHub** → **取り込む**。

プロジェクトには `.sync`(リポジトリ・ブランチ・フォルダ、取り込んだコミットとファイルごとの内容の SHA)が作られます。`.sync`・`.preview`・`.settings`・`.recovery`・`*.bak`・`*.local`(下記)・`.github-token` は取り込みも送信もしません。時刻は UTC で出ます。

### 取り込む

- リモートだけで変わったファイルは上書きし、手元だけで変えたファイルはそのまま残します。リモートで消えたファイルは、手元で変えていなければ消します。
- **取り込んだとき開いている文書が変わっていたら読み直します。** 文書の中身が変わったときだけ Undo 履歴を捨て(選択も外れます)、中身が同じなら履歴をそのまま保ちます。ほかのファイルだけが変わったときは、読み直さずにプレビューだけ作り直します。通信中はそのプロジェクトを編集できないので(下の「バックグラウンドで動きます」)、取り込みの最中に編集が混ざることはありません(万一、未保存の編集が残っていて取り込みが同じファイルを変えたときは、編集内容を `名前.local` に残して取り込んだ版を開き、その旨を表示します)。開いていたファイルが GitHub で消えていたら、同じプロジェクトの別のファイルを開きます。
- **両方で変更**されたファイルは取り込まずに、ダイアログに一覧を出します。ファイルごとに選びます。
  - **リモートの版にする**: そのファイルを GitHub の版にします。手元の版は `名前.local`(あれば `名前.local.2`、…)として同じフォルダに残ります(送られません)。
  - **手元の版を残す**: 手元のファイルをそのまま残し、次に **送る** ときに GitHub の版の上に重ねます。
  - 一覧が空になるまで **送る** は使えません(押しても説明を出して何も送りません)。

### バックグラウンドで動きます

取り込み・送る・リモートの版にする・手元の版を残す・新しいプロジェクトの取り込みは、ダイアログを閉じても裏で続きます。上のバーの右に「GitHub: 取り込み中…」「送信中…」が出て、終わると結果をトーストで知らせます(取り込みで「両方で変更」が出たときは、バーに「GitHub: 競合 N 件」が残り、タップするとダイアログが開いて一覧があります)。同時に動かせる通信は 1 つで、2 つ目を押すと「通信中です」と出ます。

通信中は、**その通信の対象のプロジェクトだけ**を編集できません(ファイルを書き換える取り込みと、読む送るが重ならないようにするためです)。文書の編集(移動・サイズ・プロパティ・Undo/Redo・ソース・部品にする・整形)、保存、ファイルの追加・名前変更、プロジェクト名の変更は「GitHub と通信中のため、このプロジェクトは編集できません」と断り、自動保存・復元用コピーと Android の一時停止時の保存もそのプロジェクトには書きません。開く・ファイルや部品の切り替え・選択・拡大縮小・「中を開く」「戻る」は使えます。ほかのプロジェクトは通信中でも普通に編集・保存でき、新しく作れます。始める前に開いている文書は今までどおり保存します。この制限は保存先の層(`lockstore.rs`)でも書き込みを断るので、画面の操作から漏れた経路があってもファイルは書き換わりません。新しいプロジェクトの取り込み中は、そのフォルダを一覧に出さず、開けません(終わると一覧に出ます。ダイアログを開いたままなら、今までどおりそのまま開きます)。終わった結果は、そのプロジェクトを開いているときだけ読み直し、別のプロジェクトを開いているときは状態の更新だけです。

### 送る

- 送る前に、開いている文書を保存します(保存に失敗したら送りません)。
- 先に GitHub のブランチが進んでいたときは、何も壊さずに止めて「先に「取り込む」を押してください」と出します。取り込んでから、もう一度送ります。

### 失敗したとき

通信の失敗、認証の失敗(トークン違い・期限切れ・権限不足)、見つからない(リポジトリ・ブランチ・フォルダ・権限)、GitHub の利用上限、フォルダが空、同名のプロジェクトがある、などを日本語で出します。途中で失敗しても、プロジェクトのファイルと `.sync` は前の状態か完了した状態のどちらかです。新しいプロジェクトの取り込みに失敗したときは、作りかけのフォルダを残しません。

### 制限

- 取り込めるのは、メニューの「GitHub から新しいプロジェクト」で作ったプロジェクトだけです(すでにあるプロジェクトを後から GitHub に結びつける操作はありません)。
- 取り込み・送信の対象は 1 つのブランチの 1 つのフォルダです。サブモジュールとシンボリックリンクは取り込みません。リポジトリが大きすぎて GitHub が一覧を切り詰めた場合は、取り込みません。
- ファイル一覧(Files)にはプロジェクト直下の `.slint` だけが並びます(サブフォルダのファイルも同期はされます)。
- 本物の GitHub での動作確認は、トークンを持つ人が手元で行ってください(開発環境にはトークンがなく、テストはすべて偽の GitHub で動きます)。

PC で画面だけ試す(偽の GitHub、通信なし): `cargo run -p app --example gh_demo -- conflicts`(`new` / `dialog` / `conflicts` / `pushed`)。

## プレビュー用の値と画面の大きさ

パネルの **プレビュー** タブで、編集中の部品(ファイルの中で選んでいる `component`)ごとに設定します。値と大きさは `.slint` には書かれず、プロジェクトのフォルダの `.preview` に保存されます(変更するたびに保存)。

- **画面の大きさ**: `360×640`(初期値)、`800×360`(OPPO A79 5G の横)、`914×411`、`1280×720` から選ぶか、「自由入力」に `800x360` の形で入れます。キャンバスの画面がその大きさになり、大きさを変えると画面全体が見えるようにズームを合わせます(部品を切り替えたとき、中を開く / 戻るとき、ファイルを開いたとき、起動時にも合わせます。ピンチで変えた後は自動では変えません)。キャンバスのタップは、`visible: false` などで実際には見えていない要素(と、その中身)を無視し、下に見えているものを選びます。
- **プレビュー用の値**: その部品の `in` / `in-out` プロパティが型つきで並びます。`bool` は 真 / 偽(選択中をもう一度押すと未設定)、`int` / `float` / `length` は数(`length` は数だけなら `px` を補う)、`string` は文字(引用符は自動。式にしたいときは先頭に `=`。書き方は「Props とプレビューの値の書き方」)、それ以外(配列・構造体・色・列挙・画像)は Slint の式のテキストです。空にすると未設定に戻ります。値はプレビューの包みの中で `部品 { プロパティ: 式; }` として渡されます。
- 保存のたびに、いったん「この値は誤り」と判定した結果を捨てて試し直します(`import` しているファイルを直したときに、前に無視された値が効くようになります)。
- 式が誤りなら、その値だけ無視されて(ほかの値は効いたまま)、行の下に理由が赤字で出ます。
- 入力欄はほかの欄と同じ入力バーを使います(タッチ操作ではタップで入力バーが開く)。

`.preview` は 1 行 1 項目で、項目はタブ区切りです。読めない行・知らない行は無視されます。ファイルの名前変更では項目も移ります。「Save as」では値と大きさは引き継がれません。読めない行は、次に保存したときに `.preview` から消えます。プロパティ名は Slint の識別子だけが有効で、部品が宣言していない `in` / `in-out` 以外の名前の値は使われません。式の中の `//`・`/*`・`*/`・文字列内の `\{` は使えません。

```text
value<TAB>main.slint<TAB>MainWindow<TAB>connected<TAB>true
value<TAB>main.slint<TAB>MainWindow<TAB>conn-text<TAB>"接続中"
size<TAB>main.slint<TAB>MainWindow<TAB>800<TAB>360
```

## ソフトキーボードと入力バー

Android のソフトキーボードが入力欄を隠すとき、キーボードのすぐ上に入力バー(項目名・入力欄・OK、高さ 52px / 部品は 44px)を出します。画面全体は動きません。

- タッチ操作(Android。デバッグビルドでは `PETARICON_FAKE_KEYBOARD` 指定時も同じ動作): Props の値欄とガイド数値は文字入力欄ではなく、タップするとすぐ入力バーが開き、バーの入力欄が最初で唯一のフォーカス先になります(Android は入力欄から入力欄へフォーカスを移すたびにキーボードを隠して出し直すため、元の欄にフォーカスしてからバーへ移すとキーボードが消えてしまうのを避けるためです)。キーボードが出ていればその上、まだなら画面下端(下の安全領域の上)にバーを置き、キーボードが出ると追従します。キーボードが 300 ms 以上隠れ続けたときだけバーを閉じ(未反映の入力は先に反映)、それより短い一時的な隠れは無視します。バーを開いてから 500 ms 以内の隠れでは閉じません。キーボードに隠れない位置でも、タッチ操作では常にバー経由で入力します。
- 対象: Props タブの値欄と、キャンバス上のガイド数値の入力(スマホなどのタッチ端末では常に、PC ではキーボードに隠れる位置にあるときだけ)。バーの入力欄に自動でフォーカスが移り、元の欄と同じ文字から始まります。
- 入力は元の欄と同じ経路に流れます(Props は 300 ms のデバウンス後に反映、OK / Enter は即反映)。OK / Enter でバーは閉じます。キーボードを閉じる(戻る)とバーも閉じ、未反映の入力(ガイド数値も)はその時点で反映します。選択の変更・Undo/Redo・タブ切り替えなどで対象が変わるとバーは閉じ、未反映の入力は元の対象に反映されます(別の要素には適用されません)。バーの外をタップしても閉じません(OK かキーボードを閉じるまで)。
- Source タブ: キーボードが出ている間、Source の編集欄(最小 60px、約 3 行)だけがキーボードの上に収まるよう縮み、Apply はタイトルの横に移ります(キャンバスとツールバーは動きません)。ただしパネルが低くキーボードの上に残る高さが約 116px 未満のときは収まりきりません。その場合は先にパネルのハンドルを上にドラッグして高くしてください(自動では広げません)。
- ファイル名・Extract のダイアログは、キーボードに隠れる場合にダイアログごとキーボードの上へ持ち上がります(Save as の一覧は縮みます)。
- PC(キーボードなし)では何も変わりません。

デバッグ用(デバッグビルドのみ。リリースビルド/APK では無効): 環境変数 `PETARICON_FAKE_KEYBOARD=<高さ(論理px)>` を付けて起動すると、その高さのキーボードが出ているものとして動きます(灰色の帯を描画)。

```sh
PETARICON_FAKE_KEYBOARD=300 cargo run -p app -- <プロジェクトのフォルダ>
```

## PC で動かす

```sh
cargo run -p app -- <プロジェクトのフォルダ>
```

フォルダを省略すると `./projects` を使います。ログは `./logs/` に出ます。

## APK のビルド

必要なもの: Rust のターゲット `aarch64-linux-android`、`cargo-apk`、Android SDK と NDK。

```sh
export ANDROID_HOME=<Android SDK のパス>
export ANDROID_NDK_ROOT=<NDK のパス>
cd crates/app
cargo apk build --release --lib --target aarch64-linux-android
```

出力は `target/release/apk/app.apk` です。release ビルドは `~/.android/debug.keystore`(パスワード `android`)で署名します(`crates/app/Cargo.toml` の `package.metadata.android.signing.release`)。署名のパスは `Cargo.toml` に絶対パス(`/root/.android/debug.keystore`)で書かれているので、別の環境でビルドするときは自分のキーストアのパスに書き換えてください。キーストアがなければ次で作ります。

```sh
keytool -genkey -v -keystore ~/.android/debug.keystore -storepass android -alias androiddebugkey \
  -keypass android -keyalg RSA -keysize 2048 -validity 10000 -dname "CN=Android Debug,O=Android,C=US"
```

パッケージ名は `dev.petaricon.editor`、表示名は `Petaricon Editor`、`min_sdk_version` は 26、`target_sdk_version` は 35 です。

## 実機へのインストール

USB デバッグを有効にして接続し、次を実行します。

```sh
adb install -r target/release/apk/app.apk
```

APK ファイルをスマホへコピーして、ファイルアプリから開いてもかまいません(提供元不明のアプリの許可が必要です)。

## 保存先と USB での受け渡し

- Android: `Android/data/dev.petaricon.editor/files/projects/<プロジェクト名>/*.slint`。保存先に権限は不要です(GitHub 同期のためだけに、通信の権限 `INTERNET` を使います。インストール時に自動で許可され、確認は出ません)。PC と USB 接続して(ファイル転送モード)、この場所を開くと `.slint` を読み書きできます。トークンはここには置かれません(アプリ専用の内部ストレージ)。
- PC: 起動引数で指定したフォルダ(省略時 `./projects`)。

保存のたびに直前の版を `<ファイル名>.slint.bak` として 1 世代残します。未保存の内容は数秒ごとに `<プロジェクト>/.recovery/<ファイル名>` へ書き出され、次回起動時に復元するか確認されます。アプリがバックグラウンドに回ったときにも自動で保存します。起動時は、復元用コピーが残っているファイルを(どのプロジェクトでも)最初に開き、なければ最後に開いていたファイルを開きます(保存先フォルダの `.last-open`)。ウィンドウを閉じるときに保存できなかった場合は、ウィンドウを閉じずにエラーを表示し、復元用コピーを書き出します。

## ログ

Rust のパニックは `crash-<unix 秒>.log` としてログフォルダに記録されます。

- Android: `Android/data/dev.petaricon.editor/files/logs/`
- PC: `./logs/`(起動したカレントディレクトリ)

## 既知の制約

- `ComponentContainer` / `component-factory` は Slint 1.18 では実験的機能です。`app` の `.slint` が使うため、`crates/app/build.rs` で `SLINT_ENABLE_EXPERIMENTAL_FEATURES` を設定しています。
- 要素の位置の取得に `slint-interpreter` の非公開 API(`internal` / `internal-highlight`)を使っています。使ってよいのは `preview` クレートだけです。
- Slint 系クレートは `=1.18.1` に完全一致で固定しています。更新は意図して行い、`preview` のテストで確認してください。
- 作らないもの: `for` / `if` / アニメーション / `states` の GUI 編集(テキストでは書けます)、GridLayout への整形、複数選択。子に `for` / `if` を含むコンテナの整形は断られます。
- ライセンス: `slint-interpreter` と `i-slint-compiler` は GPLv3 または Slint ロイヤリティフリーライセンスです。個人利用向けです。配布・販売する場合は事前に確認してください。

## クレート構成

| クレート | 役割 |
|---|---|
| `slint-doc` | `.slint` テキストの編集操作と履歴(Slint の UI に依存しない) |
| `tidy` | 整形の幾何計算(Slint に依存しない) |
| `preview` | interpreter の包み。コンパイル、埋め込み、ヒットテスト |
| `storage` | 保存先(ローカルファイル)とトークンの保管 |
| `ghsync` | GitHub 連携(REST API だけ。取り込み・送信・競合の扱い。UI に依存しない) |
| `app` | エディタ画面と、Android / PC の起動部分 |
