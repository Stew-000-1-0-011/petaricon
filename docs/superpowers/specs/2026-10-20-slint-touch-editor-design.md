# Slint タッチエディタ 設計書

- 日付: 2026-10-20
- 状態: レビュー待ち

## 1. 目的と背景

最終目的は、Android 向けのロボット多機能コントローラアプリ(3D 点群表示を含む)を作ること。UI は Slint、ロジックは Rust で書く。

本設計書はその開発を速くするための道具、**スマホ単体でも使える `.slint` のノーコードエディタ**を対象とする。コントローラアプリ本体は別の設計書で扱う。

利用者は作者本人のみ。公開や配布は想定しない。

### 1.1 利用者の要求

- 階層構造(コンテナの入れ子)はユーザーが明示的に決める
- コンテナの中では子要素を自由に配置できる
- ツールは相対的な配置(方向、順序、間隔、揃え方、padding)だけを整える
- 整形後に、間隔などを数値で調整できる
- 自前の部品を定義し、複製して配置できる
- コールバックは Rust 側で登録する(Slint の標準機能)
- 出力は、人が読んで手直しできる `.slint` そのもの
- `.slint` を手で書き換えることがあるので、エディタは知らない記述を保持する
- 主な対象は Android。スマホ単体で一通りの作業ができる。PC でも同じアプリが動く

### 1.2 検証済みの前提

`spike/` 以下の使い捨てコードで確認した。

| 検証 | 結果 |
|---|---|
| `spike/slint-wgpu-android` Slint の Android アプリに wgpu の点群を埋め込む | 実機で動作。10 万点は滑らか、100 万点で 11 fps(GPU 律速) |
| `spike/interpreter-editor` slint-interpreter で `.slint` を実行時にコンパイルして埋め込み、タップで選択、ドラッグで `x`/`y` を書き換え | 実機で動作。コンパイル 中央値 73 ms(最大 150 ms)、移動時 約 115 ms |

検証で判明したリスク:

- 埋め込みに使う `ComponentContainer` / `component-factory` は Slint 1.18 では実験的機能(`SLINT_ENABLE_EXPERIMENTAL_FEATURES`)
- 要素の位置取得(`element_positions` など)は slint-interpreter の `internal-highlight` feature の非公開 API
- 位置は、埋め込んだコンポーネントのルートを原点とする座標で返る
- Slint の公式ライブプレビューは、ドロップ位置を `x`/`y` として記録しない(自由配置の入力手段がない)。本エディタを作る理由の一つ

## 2. 範囲

### 2.1 最初のバージョンで作るもの

1. **ファイル管理**: プロジェクトフォルダ内の `.slint` を開き、編集、保存。元に戻す/やり直し
2. **キャンバス**: interpreter による本物の描画。タップで選択、自由配置コンテナ内でのドラッグ移動、ハンドルによるサイズ変更
3. **階層ツリー**: コンテナの作成、入れ子の付け替え、並び替え、削除
4. **部品パレット**: 標準部品とプロジェクト内の自前部品。選択中のコンテナの末尾に追加する(コンテナ以外を選択中ならその親に追加)。自由配置コンテナでは、表示中の範囲の左上付近に、既存の子と重ならない位置で置く
5. **プロパティパネル**: 主要な値の数値・色・文字入力と、任意プロパティの式テキスト入力
6. **整形**: 自由配置の子要素を `HorizontalLayout` / `VerticalLayout` に変換
7. **整形の解除**: レイアウトを、現在の見た目の位置で自由配置に戻す
8. **レイアウトのガイド表示**: 範囲、padding、spacing、揃え方を点線などで重ね描きし、数値を直接編集できる
9. **部品化**: 選択した要素から `component` を作る。`in property` と `callback` を宣言できる
10. **ソース表示**: 選択中の要素のソースを表示し、テキストで編集できる

### 2.2 作らないもの

- GitHub 連携(後から `storage` の別実装として足せるようにしておく)
- `for` / `if` / アニメーション / `states` の GUI 編集(テキストでは書け、表示もされる)
- GridLayout への整形
- 複数選択
- Rust のロジックを書く機能

## 3. 構成

Rust のワークスペースを 5 つのクレートに分ける。

### 3.1 `slint-doc`(文書モデル)

- `.slint` のテキストを唯一の正本とし、`i-slint-compiler` のパーサーで構文木を作る
- 編集操作は、すべて「テキストの差分」を作る。触っていない記述は 1 文字も変えない
  - プロパティの設定・削除
  - 要素の追加・削除・並び替え・入れ子の付け替え
  - レイアウトでの包み込み(整形)、レイアウトの解除
  - 部品化(要素を新しい `component` に切り出し、元の位置を部品の利用に置き換える)
- 要素の識別は「部品名 + 子の番号の経路」で行う。編集で文字の位置がずれても同じ要素を指せるようにする
- 元に戻す/やり直しは、編集前後のテキストを積む方式
- Slint の UI や interpreter には依存しない

### 3.2 `tidy`(整形ロジック)

- 入力: コンテナの矩形と、直下の子要素の矩形、グリッド幅
- 出力: 整形計画(方向、順序、spacing、padding、揃え方、警告)
- 純粋な幾何計算。Slint に依存しない
- アルゴリズムは 4 章

### 3.3 `preview`(interpreter の包み)

- コンパイル、`ComponentContainer` への埋め込み、ヒットテスト、要素の位置とサイズの取得
- 非公開 API と実験的機能を使うのはこのクレートだけにする
- Slint の各クレートは `=1.18.1` のように完全一致で固定し、更新は意図して行う

### 3.4 `storage`(保存先)

- インターフェース: プロジェクトの一覧、ファイルの一覧、読み込み、書き込み
- 最初の実装: ローカルファイル
  - Android: アプリ専用フォルダ `Android/data/<パッケージ名>/files/projects/`。権限は不要。PC とは USB 接続で受け渡す
  - PC: 起動時に指定したフォルダ

### 3.5 `app`(エディタ本体)

- エディタ画面の `.slint` と、各クレートをつなぐ処理
- Android 用(`android_main`)と PC 用(`main`)の起動部分

### 3.6 データの流れ

1. ユーザーが操作する
2. `slint-doc` がテキストを書き換え、履歴に積む
3. `preview` が再コンパイルする。連続した入力(数値入力など)はまとめて 1 回にする
4. 新しい表示に差し替え、経路で選択中の要素を選び直す。ツリー、プロパティ、ガイドを更新する
5. コンパイルエラー時は直前の表示を残し、エラーを表示する。テキストの書き換えは残す

ドラッグ中は選択枠だけを動かし、指を離したときに 1 回だけ書き換えと再コンパイルを行う。

## 4. 整形のアルゴリズム

対象は、ユーザーが選んだコンテナの直下の子要素だけ。

1. **方向**: 横に並べたとき隣り合う要素の縦範囲が重なれば横並び。縦に並べたとき横範囲が重なれば縦並び。どちらでもなければ中心座標のばらつきが大きい方向を採用し、「先に階層を分けると、きれいに整形できます」と警告する
2. **順序**: 並びの方向の座標順
3. **spacing**: 隣り合うすき間の中央値をグリッド(初期値 4px)に丸める。重なりがあれば 0 とし警告する
4. **padding**: 各辺から子要素までの距離を丸める。上下左右がそろえば `padding`、そろわなければ辺ごとに書く
5. **交差方向の揃え方**: 先頭・中央・末尾のうち、ずれの合計が最小のもの。子要素がほぼ全幅なら引き伸ばし
6. **並び方向の揃え方**: 前後の余白の比率から、先頭寄せ・中央寄せ・末尾寄せを選ぶ
7. **サイズ**: 子要素に書かれている `width` / `height` は残す。書かれていなければレイアウトに任せる
8. **書き換え**: コンテナの中にレイアウト要素を挿入し、子要素をその中へ移し、子要素の `x` / `y` を削除する。コンテナ自体は置き換えない(レイアウト要素は背景色や角丸を持てないため)
9. **取り消し**: 整形は 1 回の「元に戻す」で取り消せる
10. **対象外**: 子に `for` / `if` を含むコンテナは整形を断り、理由を表示する

**整形の解除**: レイアウト要素を取り除き、子要素を親コンテナへ戻す。各子要素には、`preview` から取得した現在の位置を `x` / `y` として書く。

## 5. 画面構成

縦画面を基本とする。

- **上部ツールバー**: 元に戻す、やり直し、保存、整形、整形の解除、部品化、ファイルメニュー
- **エラー帯**: コンパイルエラーをツールバーの下に赤い帯で表示。タップで該当箇所のソースへ移動
- **キャンバス**(画面の約 6 割)
  - タップで選択。同じ場所をもう一度タップすると親の要素へ選択が移る
  - 選択中の要素をドラッグして移動(自由配置コンテナ内のみ)。レイアウト内の要素は移動しない
  - 四隅のハンドルでサイズ変更
  - 何もない場所のドラッグでスクロール。拡大縮小はボタン(2 本指操作は Slint の対応を確認してから判断)
  - ドラッグと数値入力はグリッドに吸着
- **レイアウトのガイド**(レイアウトを含む要素の選択時)
  - レイアウトの範囲を点線の枠で示し、隅に方向の矢印を出す
  - padding の領域を薄く塗り、各辺に数値を出す
  - spacing のすき間を斜線で示し、数値を出す
  - 揃えの基準線を点線で示す
  - 数値をタップするとその場で編集できる
  - 点線は短い線分を並べて描く(Slint の線描画に点線指定がないため)
- **下部パネル**(タブ切り替え、高さはドラッグで調整)
  - ツリー / 部品 / プロパティ / ソース
- **セーフエリア**: OS のステータスバーとナビゲーションバーに重ならないよう余白を取る
- PC で横長のウィンドウの場合は、パネルを右側に置く

## 6. エラー処理とデータ保護

- コンパイルエラー: 直前の表示を残してエラー帯に表示する
- 編集操作の失敗(対象の要素が見つからないなど): テキストを変更せず、理由を表示する
- 保存のたびに直前の版を `.bak` として 1 世代残す
- 未保存の内容は数秒ごとに一時ファイルへ書き出し、次回起動時に復元するか確認する
- Rust のパニックはログファイルに記録する
- 保存は明示操作と、アプリがバックグラウンドに回ったときに行う

## 7. テスト

- `slint-doc`: 「入力 `.slint` → 操作 → 期待する `.slint`」形式のテスト。全操作で、触っていない部分が変わらないことを確認する
- `tidy`: 横並び、縦並び、ばらつき、重なり、格子状などの配置パターンで、方向・spacing・padding・揃え方を確認する
- `preview` / `app`: PC の仮想画面(Xvfb + ソフトウェア描画)で、スクリプトによるタップやドラッグと画面キャプチャで確認する
- 実機: 区切りごとに APK を作り、作者が実機で確認する
