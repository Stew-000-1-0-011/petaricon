# petaricon の拡充(複数ファイルの画面を編集する) 設計書

- 日付: 2026-10-23
- 状態: 承認済み(方針はユーザー確認済み。細部は本書の決定)
- 目的: oumuamua コントローラの画面(`crates/app/ui/*.slint`。部品ごとにファイルが分かれ、`import`・`global`・フォント・`for`/`if`・振る舞いの記述を含む)を、petaricon で壊さずに開いて編集できるようにする。GitHub との受け渡しは別の設計書で扱う。

## 1. 決まりごと

1. **利用は 1 つの節**: 編集中の部品の中にあるユーザー定義UIの利用(例: `main.slint` の中の `ManualPanel { }`)は、ツリーでもキャンバスでも 1 つの要素として扱う。利用の中の要素はタップしても選ばれず、利用そのものが選ばれる。移動・大きさの変更も利用に対して行う。
2. **中を開く**: 利用を選んで「中を開く」を押すと、その部品の定義に移る。定義が同じファイルなら編集する部品を切り替え、別のファイルなら(`import` をたどって)そのファイルを開く。「戻る」で元のファイル・部品・選択に帰る(何段でも)。未保存の変更があれば、移る前に保存する。
3. **プレビュー用の値**: 編集中の部品の `in` / `in-out` プロパティに、プレビューのときだけ使う値を入れられる。値は Slint の式のテキスト(`true`、`1`、`"文字"`、`[{name: "a"}]` など)。真偽・数・文字・長さには専用の入力(切り替え、数の入力)を出し、それ以外は式のテキスト欄にする。値は `.slint` には書かず、プロジェクトの `.preview` ファイルに部品ごとに保存する。プレビューは包み(wrapper)の中で `部品 { プロパティ: 式; }` として与える。式が誤りなら、その値だけ無視して理由を表示する。
4. **画面の大きさ**: キャンバスに置く画面の大きさを選べる。`360×640`(縦)、`800×360`(OPPO A79 5G の横)、`914×411`、`1280×720`、と自由入力。部品ごと(`.preview`)に覚える。
5. **素材**: プロジェクトのフォルダの中のフォントや画像を、`.slint` から相対パスで読めることを保証する(ファイル一覧には `.slint` だけを出す)。
6. **壊さない**: 何も変えずに保存したファイルは 1 バイトも変わらない。1 つの要素を動かしたら、その要素の `x`/`y` だけが変わる。知らない記述(`global`、`changed`、`callback`、タイマー、`for`/`if`、`@children` など)は触らない。

## 2. 確かめ方

- petaricon のテスト用に、コントローラの `crates/app/ui/` の写し(フォント込み)を `testdata/controller-ui/` に置く(写しの元のコミットを README に書く)。
- その写しで: すべての部品がプレビューでコンパイルできる/何も変えずに保存すると一致する/利用をタップすると利用が選ばれる/「中を開く」と「戻る」が往復できる/プレビュー用の値で `MainWindow` の `connected`・`page` を切り替えると対応する画面が出る/800×360 で表示できる。
- 実機(Android)向けの APK を作る。

## 3. やらないこと

- 振る舞い(タッチ処理、タイマー、`changed`)の GUI 編集。テキストのまま残す。
- `global` の値の GUI 編集(テキストで書く)。
- 利用の中の要素を、使う側のファイルから直接いじること(中を開いて編集する)。
