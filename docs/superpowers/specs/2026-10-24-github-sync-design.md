# petaricon の GitHub 連携 設計書

- 日付: 2026-10-24
- 状態: 承認済み(方式はユーザー確認済み。細部は本書の決定)
- 目的: スマホだけで、GitHub のリポジトリのフォルダ(例: `Stew-000-1-0-011/oumuamua-controller` の `ccr-1a4a2126-jaf9ht` ブランチの `crates/app/ui`)を petaricon のプロジェクトに取り込み、編集したものを同じブランチへ送れるようにする。

## 1. 方式

- 本物の git は使わず、GitHub の REST API(HTTPS)だけで行う。中身は通常の git のコミットになる。
- 認証は GitHub の fine-grained personal access token(対象リポジトリの Contents を Read and write)。トークンはアプリ専用の保存先(`.settings` と同じ場所の別ファイル `.github-token`)にだけ保存し、画面には末尾 4 文字だけ出す。ログに書かない。
- HTTP は `ureq`(rustls + webpki-roots。Android でも端末の証明書ストアに頼らない)。通信は別スレッドで行い、画面は止めない。

## 2. プロジェクトとの対応

- プロジェクトごとに `.sync` ファイル(プロジェクトのフォルダの中)に次を持つ: リポジトリ(`owner/name`)、ブランチ、フォルダのパス、取り込んだときのコミット(base)、ファイルごとの取り込んだ内容の blob SHA。
- 取り込む対象はフォルダの下のすべてのファイル(サブフォルダ込み。`.slint` 以外のフォントや画像も)。プロジェクトの中に同じ相対パスで置く。`.sync`・`.preview`・`.settings`・`.recovery` など petaricon の管理ファイルは送らない。

## 3. 操作

- **GitHub から新しいプロジェクト**: リポジトリ・ブランチ・フォルダを入れて取り込み、新しいプロジェクトを作る(名前の初期値はフォルダ名)。
- **取り込む**(既存のプロジェクト):
  - リモートで変わり、手元で変えていないファイル → 上書きする。
  - 手元で変え、リモートで変わっていないファイル → 手元のまま。
  - 両方で変わったファイル → 取り込まず、「両方で変更」の一覧を出す。ファイルごとに「リモートの版にする」を選べる(手元の版は `.bak` と同じ考え方で `<名前>.local` として残す)。
  - リモートで消えたファイル → 手元で変えていなければ消す。変えていれば残して一覧に出す。
  - 取り込みの前に、開いている文書を保存する。
- **送る**:
  - 手元で変わったファイル(base の blob SHA と、手元の内容の git blob SHA を比べる)と、手元で増えたファイルを、1 つのコミットにまとめる(blobs → tree(base の tree を土台に)→ commit(親は base)→ ブランチを更新、force はしない)。コミットメッセージは入力する(初期値「petaricon で編集」)。
  - ブランチが base から進んでいたら(更新が拒まれる)、何も壊さずに止めて「先に取り込んでください」と出す。
  - 送れたら base を新しいコミットにし、blob SHA を更新する。
  - 送る前に、開いている文書を保存する。
- 状態の表示: 最後に取り込んだ/送ったコミット(短い SHA と時刻)、手元で変わっているファイルの数。

## 4. 失敗の扱い

- 通信の失敗、認証の失敗(401/403)、見つからない(404)、上限(rate limit)を、それぞれ日本語で表示する。途中で失敗しても、プロジェクトのファイルと `.sync` は「前の状態」か「完了した状態」のどちらかにする(書き込みは一時ファイルから置き換え、`.sync` は最後に書く)。
- トークンが未設定なら、操作の前に入力を求める。

## 5. 画面

- メニューに「GitHub」を足す。ダイアログに: トークン(設定・変更)、リポジトリ・ブランチ・フォルダ(プロジェクトごと)、「取り込む」「送る」(メッセージ欄つき)、状態、「両方で変更」の一覧。ボタンは 44px 以上、文字入力はタッチでは入力バーを使う。
- 「プロジェクト」の画面に「GitHub から新しいプロジェクト」。

## 6. 確認

- GitHub API の偽物(テストの中の小さな HTTP サーバ、または API 層のトレイトの偽実装)で: 新しいプロジェクトの取り込み/リモートだけの変更の取り込み/手元だけの変更を送る/両方で変更の検出と「リモートの版にする」/ブランチが進んでいたら送らずに止まる/途中で失敗しても壊れない/トークンが画面とログに出ない。
- 本物の GitHub での確認はユーザーが行う(トークンはこの開発環境に置かない)。
