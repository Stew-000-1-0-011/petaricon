# petaricon の「この値を引数にする」 設計書

- 日付: 2026-10-24
- 状態: ユーザーが「順にお願い。よしなに」と任せたため、細部は本書で決める(不在中の決定。戻ったら確認してもらう)
- 目的: ユーザー定義UI(部品)を「引数をとって中身を返すもの」として使えるようにする。部品の中の値を引数(`in property`)にし、使う側からその引数を渡せるようにする。

## 1. 決まりごと

1. **引数にする**: 部品を編集しているとき(中を開いた状態)、部品の中の要素のプロパティ行に「引数にする」を出す。押すと名前を入れる(初期値は `<要素の id か型の小文字>-<プロパティ名>`。例 `title-text`。すでにあれば `-2` を付ける)。決めると 1 つの履歴の手で次を行う:
   - 部品のルート要素に `in property <型> 名前: 元の式;` を足す(既存の宣言の後ろ。`Op::AddDeclaration` と同じ置き場所)。
   - 元の行を `プロパティ: root.名前;` に変える。
   - 既定値が元の式なので、どの利用の見た目も変わらない。
2. **引数にできないもの**(理由を出して断る):
   - 値が書かれていないプロパティ(既定値を写せないため。「先に値を入れてください」)。
   - 式が `self` / `parent` を含む(ルートへ移すと意味が変わるため)。
   - すでに `root.<名前>` だけのもの(すでに引数)。
   - 型が分からないもの(下の 3 で決まらず、ユーザーも選ばなかったもの)。
   - 結果がコンパイルできないもの(2d2186a の検査と同じく、書き込む前に確かめる)。
3. **型**: プロパティ名から決める表を持つ(`text`→`string`、`x`/`y`/`width`/`height`/`font-size`/`border-radius`/`border-width`/`spacing`/`padding*`→`length`、`color`/`background`/`border-color`→`brush`、`visible`/`enabled`→`bool`、`opacity`→`float`、`source`→`image`)。表にないときは、引数にするダイアログで型を選ぶ(今の宣言の型の一覧 `DECL_TYPES`)。
4. **引数を渡す**: 使う側で部品の利用を選ぶと、Props に部品の `in` / `in-out` プロパティを型つきで並べる(位置と大きさの行の後ろ)。書かれていれば値、なければ空欄で、薄く既定値を添える。値の書き方は Props と同じ(文字列はそのまま、`=` で式)。空にすると渡すのをやめる(既定値に戻る)。部品が別のファイルでも `import` をたどって宣言を読む(中を開くと同じ解決)。
5. **壊さない**: 変えた行と足した宣言の行以外は 1 バイトも変えない。

## 2. やらないこと

- 引数をやめる(元に戻す)操作。元に戻すで足りる。
- 型そのものを引数にすること(Slint にないため)。
- `@children`・`for`・`if` を使った構造の引数(テキストで書く)。
- 拘束(配置の式)。別の設計書で扱う。

## 3. 確かめ方

- `testdata/controller-ui` の写しの一時コピーで: 部品の中の Text の `text` を引数にし、宣言と `root.名前` だけが変わり、プレビューの見た目が同じ/使う側で利用を選ぶと引数が Props に出て、値を入れるとプレビューが変わる/別ファイルの部品でも出る/断る場合それぞれの理由/元に戻すで一手で戻る。
