# petaricon の「付き方」(大きさが変わっても配置の意図を保つ) 設計書

- 日付: 2026-10-24
- 状態: ユーザーが「順にお願い。よしなに」と任せたため、細部は本書で決める(不在中の決定。戻ったら確認してもらう)
- 背景: 自由配置の整え(`tidy::free`)は、揃え・中央・等間隔などの関係を見つけても、結果を px で書き戻すので、入れ物(や部品の利用)の大きさを変えると意図が崩れる。CAD の拘束ほど一般的なものは要らず、子ごと・軸ごとの「どこに付くか」(Figma の constraints 程度)で足りる。これを Slint の式として書けば、解き直しは Slint 自身が行う。

## 1. 決まりごと

1. **付き方の種類**(子ごと・軸ごと。レイアウトの子には出さない):
   - 横: **左**(`x: Apx;`)、**右**(`x: parent.width - self.width - Bpx;`)、**左右**(`x: Apx; width: parent.width - Apx - Bpx;`)、**中央**(`x: (parent.width - self.width) / 2 + Cpx;`。C は 0 なら `+ 0px` を書かない)。
   - 縦: **上**・**下**・**上下**・**中央**(`y` / `height` / `parent.height` で同じ形)。
2. **.slint だけが正**: 付き方は別のファイルに持たず、上の決まった形の式そのもので表す。読み込むときに形を見分けて付き方と数(A・B・C)を出す。決まった形でない式は「式」とし、付き方の切り替えと、ドラッグ・大きさ変更での書き換えを断る(理由を出す。ソースで直せる)。
3. **切り替え**: Props の位置・大きさの行の近くに、横と縦それぞれの付き方の切り替え(左/右/左右/中央、上/下/上下/中央)を出す。切り替えると、今の見た目の位置と大きさを保つように A・B・C を計算して書き換える(1 つの履歴の手)。左右・上下にすると大きさの行は式になり、数の入力の代わりに「左右に付いています」と出す。
4. **ドラッグと大きさ変更**: 付き方を保ったまま、数(A・B・C)だけを書き換える。今の「x/y/width/height を px で書く」処理は、付き方が左・上のときにだけ使う(今と同じ結果)。
5. **推定**: 自由配置の整えの後に「付き方を推定」を出す(整えのダイアログ/結果の表示から)。各子について、入れ物の端との余白から決める: 次の順に調べる(上から最初に当たったもの): ①両方の余白が許容差以下で幅が入れ物の半分以上なら左右/②左右の余白の差が許容差以内(中心が入れ物の中心にある)なら中央/③右の余白が左より許容差以上小さければ右/④それ以外は左(縦も同様)。左右を中央より先に調べるのは、余白が等しい横長の帯は中央にも当たるが、入れ物の幅に追従させたいので左右にするため。推定の結果を一覧で見せ、まとめて書き換える(1 つの履歴の手)。
6. **キャンバスの表示**: 選んだ要素の付いている辺に小さな印(ピン)を出す。
7. **壊さない**: 変えた要素の位置・大きさの行以外は変えない。付き方が左・上のままの要素は、今と 1 バイトも変わらない。

## 2. 部品(extract)とのつながり

- 部品の中の子の付き方が `parent.width` などを使うので、部品の利用の大きさを変えると中が追従する。これで「整える → 部品にする → 利用の大きさを変える」と「部品にする → 利用の大きさを変える → 整える(中を開いて)」が、付き方を推定して書き戻すかぎり、ほぼ同じ結果になる。
- 部品のルートの大きさは、利用側で渡す引数(`width` / `height`)として振る舞う。

## 3. やらないこと

- 兄弟どうしの関係(等間隔、兄弟に揃える)を式で保つこと。整えの結果としての px のまま。
- 比率(`parent.width * 0.3`)。必要になったら足す。
- 循環する関係や不等式を解くソルバ。

## 4. 確かめ方

- 付き方ごとに: 書き出しの形/読み込みでの見分け/切り替えで見た目が変わらない/ドラッグで数だけ変わる/入れ物の大きさを変えると意図どおり動く(プレビューの位置で確かめる)/決まった形でない式は断る/推定の結果。
- `testdata/controller-ui` の写しの一時コピーで、何も変えなければ 1 バイトも変わらない。
